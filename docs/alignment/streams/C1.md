# Stream C1 (verbatim, section 6 of the orchestration brief)

Acceptance criteria below are condensed from Jira's Gherkin. Name tests after the scenarios.
Keys: HU-xx are stories; SCRUM-nn are subtasks. "Jira says" is the declared status; the work is to make the code match or exceed it.

### Stream C1: HU-03 Style quiz, HU-07 Stylist validation
HU-03 Quiz visual de estilo (SCRUM-25, Jira En curso). Acceptance: after registering, the user answers the visual questions and the hidden-styles game, the style profile is saved and they continue to measures and budget; if they abandoned at question 5, logging in again resumes at question 5; repeating the quiz from the profile updates it and keeps the history.
- SCRUM-27 verified earlier; add schema validation (styles from vocabulary, weights 0..1).
- SCRUM-26 question bank: port the 8 questions (q1 to q8) and the hidden-styles game from the prototype (`js/data.js`, `js/screens/onboarding.js`) into `backend/data/seed/quiz.json`, flagged `status: "pendiente de validación del estilista"`, served by `GET /api/quiz`.
- SCRUM-28 quiz UI in `frontend/` (one question per screen, mobile first, visual cards, hidden-styles game) replacing the 6-card text picker.
- SCRUM-29 server-side progress `PUT /api/quiz/progress`, resume after re-login, retake keeps `profile.history[]`.
- SCRUM-30 timing: `startedAt`, `completedAt`, `durationSec` saved; admin metric of average duration versus the 180 s goal.
- SCRUM-31 usability test: write `docs/usability-test-protocol.md` (script, tasks, 5-user results table). No code.
HU-07 Validación de la caja por el estilista (SCRUM-50, Jira Finalizado). Acceptance: pending AI-proposed boxes are listed; the stylist opens one and approves it, status becomes "Lista para despacho"; the stylist replaces a garment with another available in the subscriber's size, the box updates and the change and reason are logged; a box that was not approved cannot be dispatched.
- SCRUM-51 queue: `GET /api/stylist/boxes?status=PENDING_REVIEW` and a stylist panel UI.
- SCRUM-52 keep the profile and garments view (already verified).
- SCRUM-53 `POST /api/stylist/boxes/:id/approve`, `/reject`, `/replace {itemId, variantId, reason}`; replacement validated against stock and subscriber size; `box_changes` log (who, when, action, from, to, reason); unknown id gives 404; invalid transition gives 409 via the state machine from F8; the old admin raw status setter is removed or restricted to the allowed transitions.
- SCRUM-54 STYLIST role: seed script to create a stylist from env, role checks on every stylist route, tests for 401/403.
- SCRUM-55 write a `training_examples` record on every replace and reject (profile snapshot, removed, added, reason, timestamp) for HU-11.
