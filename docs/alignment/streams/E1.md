# Stream E1 (verbatim, section 6 of the orchestration brief)

Acceptance criteria below are condensed from Jira's Gherkin. Name tests after the scenarios.
Keys: HU-xx are stories; SCRUM-nn are subtasks. "Jira says" is the declared status; the work is to make the code match or exceed it.

### Stream E1: HU-09 Dispatch and tracking, HU-10 Rating, HU-14 Exchange/return by size
HU-09 (SCRUM-63, Jira Finalizado). Acceptance: when a box is approved and payment confirmed, the warehouse operator marks it dispatched, a guide is generated with the logistics operator and the subscriber gets the guide number by email; "Mis cajas" shows the current state (preparando, en tránsito, entregada); if the cycle payment is not confirmed, dispatch is blocked.
- SCRUM-64 remove `simulate-step`; the client can never change a box status; real state machine; "Mis cajas" renders real states.
- SCRUM-65 logistics adapter, manual entry of carrier and tracking number by WAREHOUSE role; delete the hardcoded tracking number.
- SCRUM-66 stock `consume` at dispatch, `release` on cancellation or rejection, everything logged in `inventory_movements`.
- SCRUM-67 transactional emails (dispatched with tracking, in transit, delivered) in Spanish through the mailer adapter.
- SCRUM-68 warehouse flow: picking list endpoint and UI (items, sizes), packing checklist including a sustainable-packaging flag, mark packed then dispatch. Dispatch returns 409 with a clear message if the box is not APPROVED or the cycle payment is not confirmed.
HU-10 (SCRUM-69, Jira Finalizado). Acceptance: after delivery the user rates each garment 1 to 5 on fit and on style, saved against the garment and profile; 3 days after delivery with no rating, a reminder email is sent; partial ratings are kept and can be completed later.
- SCRUM-70 keep the verified UI, adapt to separate fit and style scores.
- SCRUM-71 validation: integers 1..5 for fit and style, no silent default of 4, partial allowed, unique per (user, item, box), only for DELIVERED boxes.
- SCRUM-72 reminder job at 3 days, sent once, only if unrated.
- SCRUM-73 KPI: real average, no fallback; show "sin datos" when empty; flag when below 4.0.
HU-14 (SCRUM-89, Jira En revisión). Acceptance: within 5 business days of receiving the box, the user requests a size exchange with reason "talla", a return guide is generated and the other size is scheduled if in stock; outside the window the system says so and shows the conditions; with no stock in the other size it offers an exchange for another garment or a refund.
- SCRUM-90 (legal/business): `RETURN_POLICY` in config and a draft `docs/return-policy.md` labeled "pendiente de revisión legal".
- SCRUM-91 keep the verified flow, add a clear entry point inside the box detail in "Mis cajas", enforce the 5 business-day window, block duplicate returns for the same item, and implement the no-stock alternatives.
- SCRUM-92 reverse-logistics guide: a printable HTML page with return code, address, pickup date and instructions.
- SCRUM-93 inventory re-entry when the return is received: variant stock +1 with a recorded reason.
- SCRUM-94 return metric by size and by brand: returns for size reasons divided by delivered garments, goal <= 10%.
