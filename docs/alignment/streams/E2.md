# Stream E2 (verbatim, section 6 of the orchestration brief)

Acceptance criteria below are condensed from Jira's Gherkin. Name tests after the scenarios.
Keys: HU-xx are stories; SCRUM-nn are subtasks. "Jira says" is the declared status; the work is to make the code match or exceed it.

### Stream E2: HU-17 KPI panel (SCRUM-105, Jira Finalizado) and the end-to-end smoke test
Acceptance: the admin sees active subscribers, signups, monthly churn, average rating and % returns by size; when monthly churn exceeds 9% the indicator is flagged as an alert.
- SCRUM-106 write `docs/kpi-definitions.md` with exact formulas and data sources, and implement them once in `backend/kpis.js`. Churn = cancellations in the month divided by active subscribers at the start of the month.
- SCRUM-107 aggregation by month and plan; monthly `kpi_snapshots` computed by a job (the JSON-store equivalent of materialized views).
- SCRUM-108 dashboard with filters by month and plan, UI wired to the endpoints.
- SCRUM-109 alert thresholds in a `settings` collection (defaults: churn 9%, rating 4.0, returns 10%), editable by ADMIN, with tests.
- Data hygiene: a `scripts/seed-demo.js` creating demo data flagged `isDemo`; KPIs can exclude demo data. Test data must never leak into the runtime store.
- End-to-end smoke test (`tests/e2e.smoke.test.js`), fully automated against the fake adapters: register with consent, verify email, quiz, measures and budget, subscribe (token `tok_ok`), monthly batch creates a box, stylist approves (and replaces one garment), warehouse dispatches with a tracking number, delivery, rating, exchange request, KPI values reflect all of it, deletion request anonymizes the user. Also the negative paths: dispatch blocked without payment or approval, client cannot change box status, out-of-window return.
